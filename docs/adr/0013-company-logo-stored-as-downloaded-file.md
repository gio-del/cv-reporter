# Company Logo is downloaded and stored as a file, not hotlinked

A Job Listing's optional Company Logo (captured from a LinkedIn posting's DOM by the browser extension) is downloaded by the backend at save time and written to disk alongside that Job Listing's record, rather than just persisting the source image URL and having the frontend hotlink it directly. This is a narrow, deliberate exception to ADR-0008's all-flat-text-files stance — the one binary asset in an otherwise all-Markdown/YAML data store — chosen because a bare LinkedIn CDN URL is exactly the kind of link that can rot, expire, or start requiring an authenticated session, silently breaking a logo that displayed fine on save day; a downloaded copy stays stable for as long as the Job Listing record does. Considered and rejected: hotlinking the URL as-is (simplest, but fragile per the above) and having the extension itself fetch and base64-encode the image into the capture payload (keeps the backend free of third-party fetches, but bloats the JSON payload and duplicates fetch logic the backend already has a natural home for at save time).
