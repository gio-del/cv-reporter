# typst version/font pinned in one shared file, checked (not enforced) on the skill's host render path

ADR-0012 pinned typst's version and the Liberation Sans font inside `backend/Dockerfile` for the container's render path, but the `tailor-cv` skill's Render step runs the identical `typst compile` command against whatever `typst` binary and fonts already exist on the host, with nothing declaring or checking that expectation — two unsynchronized render paths that could silently produce different pagination/spacing for the same input (issue #55). `typst-version.txt` (repo root) is now the single source of truth for the pinned version and font: `backend/Dockerfile` sources it directly at build time (via `docker-compose.yml`'s backend build context moving to the repo root so the Dockerfile can `COPY` it) instead of hardcoding the version a second time, and the skill's Render step runs `plugins/cv-reporter-skills/skills/tailor-cv/scripts/preflight-typst.sh` immediately before compiling, comparing the host's `typst --version` and `fc-list` output against the file and printing a warning naming expected vs. detected on any mismatch or missing font. The check is deliberately non-blocking — the same posture as ADR-0002's human-review-is-the-real-gate principle — so a warning surfaces before Visual Review as a hint rather than a new hard gate; if `typst` is entirely absent from the host, the check no-ops and the pre-existing "typst not found" failure from `typst compile` itself is left unchanged. Output-hash-based drift detection between host and container renders was considered and deferred as a stronger but heavier future option (it would need CI to have both a typst binary and Docker available).
