# Frontend tests drive the real page and fake only the network

Frontend tests (issue #90) run on Vitest with jsdom, render the real page component inside a real `MemoryRouter` with Testing Library, drive it with `user-event`, and fake HTTP — and nothing below it — with Mock Service Worker, asserting on what the user sees and on which requests actually left the app. This is ADR-0009's backend seam drawn on the other side of the app: the backend drives its real router under `httptest.NewServer` and fakes only its outermost boundaries (`tracking.Client` for the Claude API, `atsboard.HTTPDoer` for ATS boards), so the frontend equivalent is to drive the real page and fake only `fetch`. `frontend/src/api/client.ts` therefore stays real, and the paths and query strings it builds — where the Job Listing filter and RAL sort logic actually lives — plus its shared `request()` error path are exercised rather than stubbed past. MSW runs with `onUnhandledRequest: 'error'`, so a page that starts calling a new endpoint has to declare it in the test instead of silently receiving nothing. Vitest is configured inside the existing `frontend/vite.config.ts` (tests inherit the `@` alias and plugins) with `globals: false`, which keeps `tsconfig.app.json` untouched and leaves test files type-checked by the existing `tsc -b`. Considered and rejected: module-mocking the API client with `vi.mock('@/api/client')` — a strictly lower seam that skips URL/query-string construction and the shared error handling, and forces every test to restate the client's shape; injecting the client through React context — it changes production code purely to create a test seam when a higher one already exists for free; and end-to-end browser tests (Playwright/Cypress), which would mean standing up the backend, an `ANTHROPIC_API_KEY` and `typst` in CI, a much heavier decision than this buys.
