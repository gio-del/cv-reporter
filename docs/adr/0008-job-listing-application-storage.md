# Job Listings and Applications stored as flat files, no DB

Job Listings and Applications — new dynamic, stateful data this update introduces — are stored the same way as Master Data: one file per record (`data/jobs/`, `data/applications/`), status as a plain field, rather than in a database. This was a real question given the app now has a backend and a browser extension pushing data in: those additions make a DB feel like the "obvious" choice, which is exactly why it's worth recording that we considered and rejected it. At personal-tool scale (single user, no concurrent writers, low hundreds of records at most) a DB's query/concurrency benefits don't pay for their added dependency, and flat files keep the same git-diffable, reviewable properties ADR-0003 established for Master Data.
