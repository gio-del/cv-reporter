# Render shells out to typst; backend container gains a fuller base image and mount

The app's Render step (`backend/internal/generation/render.go`) invokes the `typst` CLI exactly as the tailor-cv skill does — `typst compile --root <root> template/cv.typ output/<slug>/cv.pdf --input data=...` — rather than embedding a Typst engine or reimplementing layout in Go, keeping `template/cv.typ`'s "pure presentation, no selection logic" contract (see CLAUDE.md) intact and avoiding a second render code path to keep in sync. That requires the backend's container to actually have `typst` on `PATH` plus the Liberation Sans font the template sets, which `gcr.io/distroless/static-debian12` (the prior base image) can't provide — no package manager, no font infrastructure. `backend/Dockerfile`'s final stage moves to `debian:bookworm-slim` with `fonts-liberation` installed and a pinned typst release binary copied in, trading distroless's minimalism for that. `docker-compose.yml`'s backend service also moves from mounting only `./data:/data` to mounting the whole project root (`.:/workspace`), since `--root` must be a single directory containing both `template/` and `output/` (not just `data/`) for the JSON path typst resolves (`json("/" + sys.inputs.data)`) to work — the same constraint the skill's own `--root .` invocation already has.
