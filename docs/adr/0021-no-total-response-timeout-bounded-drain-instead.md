# No total-response timeout; a request deadline and a bounded drain instead

The backend's `http.Server` is configured explicitly (`ReadHeaderTimeout` 10s, `ReadTimeout` 60s, `IdleTimeout` 120s) rather than taking `http.ListenAndServe`'s defaults, which impose no limits at all — a default that was near-irrelevant while the listener was localhost-only and became worth fixing once LAN-reachable mode (issue #57) made the same process reachable from other devices. `WriteTimeout` is deliberately set to `0`, explicitly and with a comment, because Go runs it from the end of the header read to the end of the response write, making it a cap on total handler duration: `POST /api/generations` makes four Claude calls (Selection+Rewrite, Cover Letter drafting, then RAL estimation's two-call web-search pattern, ADR-0011) and `POST /api/job-listings` adds RAL resolution plus Application Method inference at save time, so any value tight enough to be a meaningful limit breaks the pipeline's core feature and any value loose enough to be safe protects nothing. Its failure mode is also the wrong one here — it tears down the connection while the handler keeps running, so the user sees a network error while the server goes on spending Claude tokens.

The bound those routes get instead is a request context deadline (10 minutes, `withRequestDeadline`, applied to the Claude-calling routes only), because the generation path is already context-aware end to end, so a deadline actually cancels the outbound call; it also makes an abandoned browser request stop its Claude calls for free. Complementing it, SIGINT/SIGTERM now drain rather than kill: `signal.NotifyContext` plus `Server.Shutdown` with a 15s window, followed by cancelling the `BaseContext` every request derives from, so a request that outlives the drain is cancelled rather than severed at the socket (`Shutdown` alone never cancels request contexts, which would leave a mid-Claude-call request blocking the drain for minutes). `docker-compose.yml` gets `stop_grace_period: 30s` so Docker's 10s default cannot SIGKILL the process mid-drain.

Considered and rejected: a `WriteTimeout` long enough to be safe (protects nothing, and mislabels a live Generation as a failure); a job queue that survives a restart and resumes interrupted Generations (out of proportion — a Generation is interactive and human-reviewed, ADR-0002); making `typst`/`pdftotext` shell-outs context-aware so the drain can interrupt them (a compile takes seconds and finishes inside the window, and its output under `output/` is regenerable derived data, not Master Data — left for whenever it is needed). None of this is a hardening measure: ADR-0004's localhost-only default and issue #57's tradeoffs (shared static token, no TLS) are unchanged, and this does not make LAN mode safe to expose to an untrusted network.
