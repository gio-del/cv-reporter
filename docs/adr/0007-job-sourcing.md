# Job sourcing via ATS public APIs and a browser extension, not scraping

Job Listings are populated three ways: manual paste (URL/text, as today), ATS-native public job-board APIs (Greenhouse, Lever, Ashby — documented, used as intended), and a browser extension. The extension does not scrape LinkedIn independently — it reads content already rendered in the user's own authenticated browser session (the job post they're currently viewing) and hands it to the app, the same category of behavior as a "save to app" extension. This is a considered gray area, not a clean green light: LinkedIn's ToS broadly restricts automated data collection, and reading DOM content from a page the user is legitimately viewing is a materially different risk than crawling/scraping at scale, but it is not officially sanctioned by LinkedIn either. General-purpose LinkedIn scraping (crawling listings LinkedIn hasn't served to this user's session) is explicitly out of scope — see ADR-0006 for the same boundary applied to application submission.
